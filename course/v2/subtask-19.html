Same account, same agent, same question. The only thing that changed is what it can reach.

In sub-task 15 you asked an agent to cite the policy behind its verdict on A000012 and it invented one. You proved the invention with grep and wrote it down.

Nothing about the agent has changed since. Same model, same dossier, same question, same prompt if you want it. The only difference is that three policy documents now exist in a place it can reach.

This sub-task is short because the work is done. What's left is to look at the difference carefully enough to be able to describe it to someone paying for it.

What you'll understand and do

  • Re-judge A000012 with Skills available and verify the citation against the file
  • Compare the ungrounded and grounded verdicts side by side
  • State what Skills changed — and what they didn't

Concept

The one idea

Skills don't make the model smarter. They make it accountable.

It's tempting to describe grounding as an accuracy improvement, and that undersells it in a way that will cost you an argument with a client eventually.

The ungrounded verdict on A000012 may well have been right. A privileged Vault grant unused for ten months is a finding under almost any dormancy standard you could imagine, and the model imagined one. It reached a defensible conclusion by an indefensible route.

The distinction that matters

Ungrounded: the conclusion happens to be right. There is no way to check it short of already knowing the answer, and the citation attached to it is false.

Grounded: the conclusion is traceable to a clause that exists, which you can open and read in four seconds. If you disagree, you can argue with the reasoning rather than with the model.

An access review is not a prediction task. It is a document handed to an auditor who will pull three findings at random and ask you to justify them. Traceability is not a nice-to-have; it is the product.

There is also a concrete accuracy gain, and it is worth naming because it shows what grounding actually buys. The invented standard said 90 days and had one requirement. The real one says 180 days and has two — an approving ticket as well as recent activity. The grounded verdict on A000012 can breach both and say so. The ungrounded one couldn't, because it didn't know the second requirement existed.

Do this

Task 1

Re-judge the account

  1. Run your sub-task 14 agent on A000012 again, with the Skills available.

    Why: change nothing else. Same dossier, same schema constraint, same system prompt. A controlled comparison needs exactly one variable to move, and this is the cheapest controlled experiment in the course.

  2. Verify the citation against the file — the same grep you ran to disprove the last one.

    Why: expect a citation of the Privileged Access Standard by title, with no section number, because that document has no sections. If it still produces a "§3.2", your Skill either isn't loading or doesn't say that the document is unnumbered. Both are fixable and both are worth knowing about now.

    terminal 
    grep -n "180" data/2026-Q3/policies/privileged-access-standard.md
cat data/2026-Q3/policies/privileged-access-standard.md
  3. Check the rationale reflects what the standard actually requires.

    Why: three things should now be present that couldn't have been before. The threshold is 180 days, not an invented 90. Both requirements are addressed — the last login of 2025-11-14 against a quarter-end cutoff of 2026-04-03, and the absence of an approving ticket for a grant made by gateway.provisioning on 2025-05-18. And the break-glass carve-out is considered and dismissed: gabriel.villa is not in service_accounts.json, so it doesn't apply.

    That third one is the tell. An agent that mentions an exemption it then rules out has actually read the document. An agent that never mentions it may simply not know it exists.

Stuck?

The verdict didn't change at all. Check the Skill loaded — restart if you created .claude/skills/ this session. Then check the description: if it doesn't clearly signal "privileged access, dormancy, ticket requirements", Claude may not have judged it relevant to a dossier about a Vault admin.

It still cites a section number. Your Skill quotes the policy but doesn't say the document is unnumbered. Add that sentence explicitly. It's one line and it removes an entire class of error.

It now says this isn't a finding. Interesting — and worth investigating rather than "fixing". Usually it means the Skill's break-glass carve-out is over-applying, or the as-of date in your dossier is wrong. A000012 breaches both requirements by a wide margin under any reading, so a clear verdict points at something genuinely broken.

What Skills gave the agent is knowledge. What it still lacks is reach — it knows only what you decided to put in the dossier, and it cannot go and look anything up. Theme E is building block three: tools.
