Store a secret so it can't leak, then talk to Claude Code

Depends on: Sub-task 3 — you need the kit installed Time: ≈ 60 min Type: setup + first contact
First appearance
API key .env .gitignore Claude Code

Handling a credential correctly is the first professional habit in this course. Do it before you install anything that uses one.

You're about to hold a credential that can spend money. Before you use it, you'll make sure it can't accidentally end up somewhere public — and, more importantly, you'll prove that rather than assume it.

Then you'll meet Claude Code and ask it the first question of the course. Not to build anything: just to describe the repository back to you, so you can watch how it explores a codebase it has never seen.

What you'll understand and do

  • Explain what an API key is and why it never belongs in a file that gets committed
  • Store the key in .env and prove git is ignoring it
  • Run Claude Code and read how it investigates a repository

Concept

The one idea

"I was careful" is not evidence. git check-ignore is.

Leaked credentials are among the most common serious security incidents in software, and they almost never happen because someone was reckless. They happen because someone was careful and assumed the protection was working. The habit worth building today is small: after you set up the protection, run a command that proves it.

You'll do this twice — once with git status (the file doesn't appear) and once with git check-ignore (git names the rule that's hiding it). The second is the stronger evidence, because a file can be absent from git status for boring reasons that have nothing to do with your protection.

What is an API key?

A long secret string that identifies your account to a service. Anyone holding it can make requests that bill you, so it's a password, not a username. Yours comes from the Anthropic Console — your instructor will tell you whether to create one or use a supplied key.

Treat it exactly like a password: never paste it into a chat, a ticket, a screenshot, or a file you might commit.

What are .env and .gitignore?

.env is a plain text file of NAME=value lines holding settings that differ per machine — including secrets. The convention is that a project commits a .env.example showing which names are needed, with the values left blank, and each person fills in their own .env.

.gitignore lists files git should pretend not to see. This repository's .gitignore already contains a line reading .env — so the protection is in place before you arrive. Your job is to confirm it, not create it.

What is Claude Code?

Claude, running in your terminal with the ability to read and edit files, run commands, and search your project. That's the difference from a chat window: it doesn't need you to paste code in, because it can go and look.

It's the tool you'll use for essentially everything from here. Today you only ask it to look and report.

Do this

Task 1

Store the key, then prove it's hidden

  1. Copy the example file to a real one.
    terminal · macos 
    cp .env.example .env
    powershell · windows 
    Copy-Item .env.example .env

    Why: .env.example is committed and shows the shape; .env is yours and is ignored. It contains one line — ANTHROPIC_API_KEY= — waiting for a value.

  2. Open .env in VS Code and paste your key after the equals sign.

    Why: no quotes, no spaces around the =, no trailing blank. The line should read ANTHROPIC_API_KEY=sk-ant-… and nothing else. Save the file.

  3. Prove git can't see it.

    Why: this is the whole point of the sub-task. Two commands, two different kinds of evidence.

    terminal 
    git status --short
git check-ignore -v .env

    The first should not list .env anywhere. The second should answer with the rule that's hiding it:

    git check-ignore -v .env
    .gitignore:13:.env .env

    Read that as: line 13 of .gitignore, containing the pattern .env, is what's ignoring the file .env. Silence from this command would mean the file is not ignored — stop and fix it before going further.

Stuck?

git check-ignore printed nothing. Nothing means not ignored. Check you're in the repository root and that the file is called exactly .env — not .env.txt, which is what Windows Notepad will silently do to you. In VS Code, the filename in the tab is the truth.

I can't see the file — it vanished. Files starting with a dot are hidden by default. In VS Code's file tree they're visible; in Finder press ⌘ + Shift + . to toggle them.

I already committed my key by accident. Tell your instructor and rotate the key immediately — treat it as public from that moment. Removing it from git history is possible but fiddly, and rotating is faster and safer regardless.

Task 2

Install Claude Code and ask it about the repository

  1. Install Claude Code.
    terminal · macos 
    curl -fsSL https://claude.ai/install.sh | bash
    powershell · windows 
    irm https://claude.ai/install.ps1 | iex

    Then confirm with claude --version, which prints a version followed by (Claude Code). Close and reopen your terminal first if it says the command isn't found.

  2. Start it in the project folder and log in.
    terminal 
    claude

    First run sends you to a browser to sign in. Follow your instructor's guidance on which account to use.

    Wait — didn't I just set up an API key for this?

    No, and this trips people up. Two separate things are going on. Claude Code signs in with your account in the browser. The key in .env is for the kit's own code — the one test that calls Claude directly, and the pipeline you build later. They're independent, and you need both.

  3. Ask it to describe the repository.

    Why: a deliberately open question, so you can watch how it decides what to look at. Type this at the prompt:

    prompt 
    Describe this repository. What is it for, what are the main folders, and what would I run to check that it's working? Don't change anything.

    Watch the middle, not just the answer — the files it chooses to open, in what order. That's it forming a picture, and it's roughly what you did by hand in sub-task 3.

  4. Check its answer against what you already know.

    Why: you're the only quality control here, and you're in the rare position of knowing the right answer. Did it identify pytest -m "not api" as the green light? Did it get the folders right? Did it state anything confidently that you know to be wrong?

    Note anything it got wrong. You'll want it in sub-task 6.

Stuck?

It asks permission before reading files. Expected. Claude Code asks before acting, and you approve each one. That prompt is a feature — read what it's asking for rather than approving on reflex.

Can I use the kit's bootstrap script instead? Yes, but note it installs Claude Code via npm, which needs Node. If Node isn't installed the script warns and skips that part — it won't block your setup, but you'll still need the native installer above.

How do I get out? Type /exit, or press Ctrl + D twice.

Should I paste Meridian's data into the prompt? No — and this becomes a formal rule in sub-task 7. Claude Code can open files itself. Pasting bulk data in is slow, expensive, and unnecessary.

You're done when

You have two things:

  • git check-ignore -v .env naming the .gitignore rule that hides your key — and git status that doesn't mention .env at all
  • A Claude Code transcript describing this repository, which you've read critically and compared against what you learned in sub-task 3

Commit your progress before moving on — your .env won't be included, which is the point.
