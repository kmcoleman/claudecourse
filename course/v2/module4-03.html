Export something the client can act on

Depends on: Module 4 · 2 — you need recorded decisions to export Time: ≈ 45 min Type: elective — not a building block
First appearance
decisions log CSV injection Blob download print stylesheet

Two of these are formatting. One of them is a vulnerability you will ship to a client if nobody tells you about it.

The deliverable at the end of an access review is not a dashboard. It is a file: one row per finding, the model's recommendation, the human's decision, the reason, who decided and when. Somebody downstream has to revoke access based on it, and somebody else has to still be able to read it in an audit two years from now.

Which means it has to leave the browser.

What you'll understand and do

  • Emit a CSV that survives quoting, commas in prose, and Excel
  • Neutralize formula injection before it reaches a spreadsheet
  • Trigger a download from a static page with no server and no library
  • Produce a printable report with a print stylesheet instead of a PDF dependency
  • Stamp the export with the provenance an auditor will ask for

Concept

The one idea

A review artifact is evidence. Evidence needs provenance, not just content.

Two files with identical rows are not equally useful. The one that also states which quarter, which export directory, which commit produced the findings, when the review was completed and who completed it can be defended. The other one is a spreadsheet somebody emailed.

You already have every one of those facts. Sub-task 39 had you record the commit hash for exactly this reason. Putting them in a header block costs six lines and is the difference between an artifact and a screenshot.

CSV injection — the one genuine vulnerability in this module

A cell beginning =, +, - or @ is interpreted by Excel, Sheets and LibreOffice as a formula, not text. A rationale or a reviewer note starting with one of those characters can execute when your client opens the file — that's the whole attack, and it has a CVE history.

Your findings contain model-authored prose derived from client data, and your notes contain free text typed by a human. Both are untrusted by the standard sub-task 28 established. Prefix any cell starting with those characters with a single quote, which every spreadsheet reads as "this is text".

RFC 4180 in one paragraph

Quote every field. Double any quote inside a field. Use \r\n between rows. Do that unconditionally and you never have to reason about whether a particular rationale happens to contain a comma — and a rationale will, on your client's data, in the finding that matters.

Prepend a UTF-8 BOM (\ufeff) so Excel on Windows doesn't mangle non-ASCII names. Ugly, universally necessary, one character.

Why print instead of PDF. Generating a PDF in the browser means a library, which means a dependency, a bundle step and a supply chain. @media print plus the browser's own "Save as PDF" produces a perfectly good document, ships as forty lines of CSS, and works offline in three years. The constraint that there be no new dependencies isn't arbitrary — it's what keeps the deliverable openable.

What goes in the export that isn't on screen

Undecided findings. Export them with an empty verdict rather than dropping them. A row that says "nobody looked at this" is one of the most important rows in a compliance artifact, and silently omitting it turns an incomplete review into one that looks complete.

Task 1

The CSV

  1. Write the cell encoder, injection guard first.

    Why: one function, applied to every cell including the headers, so there is no path through your code that emits an unescaped value. Guard before quote — the leading apostrophe has to be inside the quoted field.

    reviewer/index.html — script 
    function csvCell(value) {
  var s = (value === null || value === undefined) ? "" : String(value);
  // Excel, Sheets and LibreOffice execute cells starting with these. Neutralize.
  if (/^[=+\-@\t\r]/.test(s)) s = "'" + s;
  return '"' + s.replace(/"/g, '""') + '"';
}

function toCsv(rows, columns) {
  var lines = [columns.map(csvCell).join(",")];
  rows.forEach(function (r) {
    lines.push(columns.map(function (c) { return csvCell(r[c]); }).join(","));
  });
  return lines.join("\r\n");
}
  2. Build the row set from findings joined to decisions, keeping the undecided ones.

    Why: iterate the findings, not the decisions. Iterate the decisions and a finding nobody touched disappears from the deliverable — which is the exact failure mode that makes an incomplete review indistinguishable from a complete one.

    reviewer/index.html — script 
    var COLUMNS = [
  "account_id", "employee_id", "app", "entitlement", "category", "severity",
  "model_recommendation", "human_verdict", "reason", "reviewer", "decided_at",
  "policy_citations", "confidence", "rationale"
];

function exportRows(findings) {
  return findings.map(function (f) {
    var d = decisions[keyOf(f)] || {};
    return {
      account_id: f.account_id, employee_id: f.employee_id,
      app: f.app, entitlement: f.entitlement,
      category: f.category, severity: f.severity,
      model_recommendation: f.recommendation,
      human_verdict: d.verdict || "",            // empty === nobody looked
      reason: d.note || "",
      reviewer: d.reviewer || "",
      decided_at: d.decided_at || "",
      policy_citations: (f.policy_citations || []).join("; "),
      confidence: f.confidence,
      rationale: f.rationale
    };
  });
}
  3. Trigger the download with a Blob and a synthetic click.

    Why: no server involved — the file is constructed in memory and handed to the browser's download machinery. Revoke the object URL afterwards; a page a reviewer keeps open for an hour shouldn't leak a blob per export.

    reviewer/index.html — script 
    function download(filename, text, mime) {
  var blob = new Blob(["\ufeff" + text],       // BOM so Excel reads UTF-8
                      { type: mime + ";charset=utf-8" });
  var url = URL.createObjectURL(blob);
  var a = document.createElement("a");
  a.href = url;
  a.download = filename;
  document.body.appendChild(a);
  a.click();
  document.body.removeChild(a);
  URL.revokeObjectURL(url);
}

document.getElementById("exportCsv").addEventListener("click", function () {
  var csv = toCsv(exportRows(findings), COLUMNS);
  download("meridian-uar-" + QUARTER + "-decisions.csv", csv, "text/csv");
});
  4. Open it in a spreadsheet and try to break it.

    Why: type a note containing a comma, a double quote, a newline and =1+1, then export and open. All four should come back as literal text in one cell. This takes ninety seconds and is the only proof that any of the above works.

Task 2

The printable report

  1. Add the provenance header.

    Why: quarter, export directory, commit hash, generated-at, reviewer, and the four counts. Everything except the commit is derivable in the page; type the commit into a field and store it, or read it from a meta.json your pipeline writes. The second is better and takes ten lines.

    what the header states 
    Meridian Regional Energy — user access review
Quarter        2026-Q3
Export         data/2026-Q3
Pipeline       commit a1b2c3d
Reviewed by    
Completed      2026-08-07T14:22:10Z
Findings       9    approved 6   denied 1   deferred 1   undecided 1
  2. Write the print stylesheet.

    Why: hide the controls, repeat the table header on every page, and stop rows splitting across a page break. Those three rules are most of what separates a printed web page from a document.

    reviewer/index.html — style 
    @media print {
  .controls, .exportbar, button, input { display: none !important; }
  body    { font: 10.5pt/1.45 Georgia, serif; color: #000; background: #fff; }
  table   { width: 100%; border-collapse: collapse; }
  th, td  { border: 1px solid #999; padding: 4px 6px; }
  thead   { display: table-header-group; }   /* repeat header on every page */
  tr      { break-inside: avoid; }
  details { break-inside: avoid; }
  details[open] summary { display: none; }   /* expanded rationale, no toggle */
  a::after { content: " (" attr(href) ")"; font-size: 8pt; }
}
  3. Expand every rationale before printing, and say so.

    Why: a <details> that's closed on screen prints closed, so your reasoning vanishes from the PDF. One line — open them all in a beforeprint handler — and the printed artifact carries the justification that makes it defensible.

    reviewer/index.html — script 
    window.addEventListener("beforeprint", function () {
  document.querySelectorAll("details").forEach(function (d) { d.open = true; });
});
  4. Print to PDF and read the whole thing as if you didn't build it.

    Why: this is the artifact. If page three is a table header floating alone, or the rationale column ran off the right edge, you'd rather know before it's attached to an email.

  5. Write down who this goes to and what happens next.

    Why: a deliverable with no downstream action is a report, and reports are where access reviews go to die. Somebody has to actually revoke the accounts.

Stuck?

Excel splits one rationale across three columns. An unescaped comma. Every field goes through csvCell, headers included — check for a join(",") somewhere that skipped it.

Accented names show as mojibake. Missing BOM. The "\ufeff" prefix in the Blob constructor fixes it; Excel on Windows will not otherwise assume UTF-8.

Nothing downloads and there's no error. Some browsers ignore a synthetic click on an anchor that isn't in the document. Append it to document.body before click(), as in the snippet.

The print preview is one enormous page. Almost always a container with height or overflow: hidden. Print layout ignores your viewport; let the table be as tall as it is.

Do undecided findings belong in the export? Yes, with an empty verdict. Omitting them makes an incomplete review look complete, which is the single worst thing a compliance artifact can do.

You're done when
  • An Export decisions button produces a quarter-stamped CSV with one row per finding — including undecided ones
  • Commas, quotes, newlines and leading = survive as literal text in a spreadsheet
  • Both the model's recommendation and the human's verdict appear as separate columns
  • The printed report carries quarter, commit, reviewer, timestamp and counts
  • Rationales are visible in the printed output
  • Still no dependencies

You have a shareable review artifact. The loop back to the pipeline is the last thing left, and it's optional.

If you're curious

  • OWASP on CSV injection — short, and the examples are worth seeing once because they're more capable than the =1+1 demo suggests.
  • MDN on printing — break-inside, table-header-group and @page margins cover almost every layout complaint you'll have.
  • Diff your export against findings.json with a script and confirm every finding appears exactly once. That check belongs in your eval suite next to the schema validator from sub-task 12 — a deliverable that drops rows is a correctness bug, not a UI bug.
