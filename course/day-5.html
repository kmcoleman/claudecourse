Cycle 1

A fresh quarter, same company

≈ 90 min
Concept

To test transfer honestly, you need data your pipeline has never seen — but from the same company, so any failure is about your code, not a different world. The kit's generator does exactly this: give it a new seed and a new quarter, and it rebuilds Meridian from scratch — same 22 apps, same roles, same policies, same SoD matrix — but with a completely new cast of people and a new set of specific findings.

What stays fixed seed to seed: the apps (Atlas ERP, MeridianPay, Gateway, Active Directory, Vault, and the rest), the role vocabulary, the five policies, the SoD matrix, and the service-account registry — marcus.pipeline and emergency.admin are constants. What changes: every person's name, email, and employee ID; which employee is the AP Clerk who also holds AP Manager; which one is the Controller covered by the ACP-4.2 exemption; which contractor's SOW has lapsed; and the exact finding counts. A new seed is a new exam sat by the same company.

Pattern vs. memorization

Your pipeline learned the pattern if it flags whoever holds AP Clerk + AP Manager this quarter, exempts whoever the current Controller is, and catches whichever contractor is now past SOW. It memorized Q3 if it leans on a specific Q3 name, employee ID, or exact count — if canonical_id == "MRE-00902", or assert findings == 214. Memorization passes Q3 and fails silently on Q4.

Cycle 2

Run your pipeline against Q4

≈ 90 min
Concept

Now run yesterday's pipeline — unchanged — against Q4 and watch what happens. Two kinds of failure show up here, and the second is more dangerous than the first.

A crash is honest: the code errors because it expected a specific Q3 employee ID that Q4 doesn't have. A wrong answer is quiet: the run finishes clean but the findings are subtly off — this quarter's Controller gets flagged even though the ACP-4.2 exemption covers her, because your pipeline recognized the Q3 Controller by ID and never learned the rule. Today you learn to distrust a green run until you've checked it's actually right.

Task
  1. Run the pipeline against Q4, unchanged.

    Why: this is the honest transfer test — same code, a quarter it's never seen, no edits yet.

    Claude Code prompt 
    Run run_review(export_dir='data/2026-Q4') with no code changes.
Show me exactly what happens — errors, or findings.
    run_review(export_dir='data/2026-Q4') KeyError: 'MRE-00902' (policy-applier, hardcoded ACP-4.2 exemption list) ... pipeline halted
  2. Diagnose the crash.

    Why: the first error names one memorized Q3 detail. Find out which specific value was baked in and where.

    Claude Code prompt 
    Trace this KeyError. Which Q3-specific value did we hardcode, in
which file, and why doesn't Q4 have it?
  3. Hunt for the quiet wrong answers, not just the crash.

    Why: fixing the crash won't be enough if other Q3 specifics produce wrong findings silently. Get ahead of them now.

    Claude Code prompt 
    Beyond this crash, scan the pipeline for anything tied to specific
Q3 people, IDs, or exact counts — hardcoded names, allowlists, or
asserts like "findings == 214" — that would pass silently but be
wrong for Q4.
    Stuck?

If any of those is wrong, a Q3 assumption is still baked in.

    Why: commit the list of memorized specifics before you start changing code, so you have a clean record of what needed fixing.

Cycle 3

Fix the memorization

≈ 90 min
Concept

Now do the actual generalizing. Every place your pipeline named a specific Q3 person, ID, or count comes out and gets replaced with the rule it should have used all along. The ACP-4.2 exemption shouldn't check canonical_id == "MRE-00902"; it should check the rule — a Finance & Accounting Controller holding AP Manager + Vendor Admin with a documented compensating control. Rules travel; identifiers don't.

policy-applier.py (memorized → pattern) 
# WRONG — memorized Q3
if canonical_id in {"MRE-00902"}:          # the Q3 Controller
    exempt = True

# RIGHT — the rule, works every quarter
if (title == "Controller"
        and department == "Finance & Accounting"
        and has_documented_exemption(person, "ACP-4.2")):
    exempt = True
