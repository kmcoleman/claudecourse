What is an agentic system?

An ordinary program follows fixed instructions: "if column A equals X, flag it." An agentic system hands a goal to an AI model that can reason, use tools, read files, and decide its own next step — "review these access grants against this policy and tell me what's wrong." You describe the outcome; the agent works out the how. This week you build one, piece by piece.

Meet Meridian Regional Energy — a regional gas & electric utility, 22 applications, roughly 1,200 employees, and a compliance team drowning in spreadsheets. They are your client all week. Their access data is fragmented, their policies live in a PDF binder, and a regulator is asking questions nobody can answer quickly. You're going to fix that.

  • Subagents (Day 4) — specialists that split the work so it scales
  • The pipeline — the whole thing running end to end against real data

Cycle 2

Your development environment

≈ 90 min
Concept

Three tools sit under everything an engineer does. You'll install two of them now and meet the third. None is complicated once you know what it's for.

What is a terminal?

The terminal (also "command line" or "shell") is a window where you type commands as text instead of clicking buttons. It looks intimidating and isn't — it's just a different door into your computer. On Windows it's called PowerShell or Terminal; on Mac it's Terminal. You'll run everything this week from here.

What is VS Code?

Visual Studio Code is a free text editor built for code. It's where you'll read the files Claude Code writes, open the terminal, and see your whole project in one window. Think of it as the room you work in.

What is git?

git is a tool that tracks the history of your files. Every time you finish a piece of work, you take a labeled snapshot called a commit — a permanent save point you can always return to. It's the single most important safety net you have: commit often, and no mistake is ever fatal. Here are the four commands that make up almost everything you'll do with it:

The full git vocabulary — you'll practice each one below:

  • git init — start tracking a folder ("this project's history begins now")
  • git status — ask "what have I changed since my last save point?"
  • git add . — stage your changes: mark which files go into the next snapshot
  • git commit -m "..." — take the snapshot, with a short message describing it
Task
  1. Install VS Code, then open it.

    Why: it's your workspace for the rest of the week. Download from the official site and run the installer for your operating system.

    Browser 
    https://code.visualstudio.com/download
    Stuck?

    Windows: choose the "User Installer" for your architecture (almost always x64). Mac: unzip and drag VS Code into Applications. If it won't open on Mac, right-click the app and choose "Open" once to clear the security prompt.

  2. Open the built-in terminal in VS Code.

    Why: keeping your editor and terminal in one window is how you'll work all week. Use the menu: Terminal → New Terminal.

  3. Install git, then verify it.

    Why: --version is the universal "are you installed and reachable?" check. If it prints a version number, the tool is ready.

    Browser 
    https://git-scm.com/downloads
    Terminal 
    git --version
    git --version git version 2.45.1
    Stuck?

    "command not found"? Close the terminal completely and open a new one — freshly installed tools often aren't visible until you do. If it still fails on Windows, reboot; the installer updates a system setting that needs a restart to take effect.

  4. Create a throwaway practice folder and start tracking it with git.

    Why: you'll practice the full commit cycle once, on files that don't matter, so it's muscle memory before it counts. git init tells git to begin recording this folder's history.

    Terminal 
    mkdir git-practice
cd git-practice
git init
  5. Create a file, check the status, then make your very first commit.

    Why: this is the loop you'll repeat hundreds of times. status shows what changed, add stages it, commit snapshots it with a message. Do it once here and it stops being scary.

    Terminal 
    echo "hello" > notes.txt
git status
git add .
git commit -m "My first commit"
    git status Untracked files: notes.txt nothing added to commit but untracked files present git commit -m "My first commit" [main (root-commit) a1b2c3d] My first commit 1 file changed, 1 insertion(+)
    Stuck?

    git asks for your name and email? That's normal on first use — it wants to label your commits. Run the two git config --global lines it suggests, then commit again. Ask Claude Code later if the message is unclear.

Checkpoint

You're done with Cycle 2 when VS Code is open, git --version prints a number, and you've made at least one real commit in your practice folder. You now know the commit loop — from here on we'll just say "commit."

Cycle 3

Python and a clean sandbox

≈ 90 min
Concept

The access-review code you build this week runs on Python. You won't need to master the language — Claude Code writes most of it — but it has to be installed, and it has to run in a clean, isolated space so this project's tools never collide with anything else on your machine.

What is Python?

Python is a programming language known for being readable and beginner-friendly. It's the standard language for data work, which is why we use it for access reviews. When you run python something.py, you're asking Python to execute the instructions in that file.

What is a virtual environment (venv)?

A venv is a private sandbox for one project's Python packages. Without it, everything you install piles into one shared space and projects start breaking each other. With it, this project's tools live in their own folder. When the venv is active, your terminal prompt usually shows (venv) at the start of the line.

Task
  1. Install Python, then verify it.

    Why: same --version check as git. On Windows, tick "Add Python to PATH" in the installer — it saves a headache later.

    Browser 
    https://www.python.org/downloads
    Terminal 
    python --version
    python --version Python 3.12.4
    Stuck?

    "command not found" or wrong version? On Mac, try python3 --version instead. On Windows, if it opens the Microsoft Store, you skipped "Add to PATH" — re-run the installer and tick that box.

  2. Create a virtual environment for this course.

    Why: this makes the sandbox. It creates a venv/ folder that will hold every package you install this week.

    Terminal 
    python -m venv venv
  3. Activate the venv.

    Why: creating it isn't enough — you have to step inside. Look for (venv) to appear at the front of your prompt.

    Terminal · Mac 
    source venv/bin/activate
    Terminal · Windows 
    venv\Scripts\activate
    Stuck?

    Windows blocks the script? If you see a message about "running scripts is disabled," you need to allow local scripts once. Ask Claude Code — it'll give you the exact one-line command for your setup and explain what it does.

  4. Install one package to confirm the sandbox works.

    Why: requests is a tiny, harmless package. If it installs into your active venv without error, your Python setup is sound.

    Terminal 
    pip install requests
    pip install requests Successfully installed requests-2.32.3 ...
Checkpoint

You're done with Cycle 3 when python --version prints a 3.x number, your prompt shows (venv), and pip install requests finishes with "Successfully installed." Your Python bench is clean and isolated.

Cycle 4

API keys and Claude Code

≈ 90 min
Concept

Now the star of the week. Claude Code is a program that turns Claude into a working coding partner living right in your terminal — it reads your files, writes and edits code, runs commands, and explains what it did, all from plain-English instructions. To use it, it needs a key that proves the requests are yours.

What is an API key?

An API key is a long secret string — like a password for programs. It tells Anthropic's servers "these requests belong to this account." Anyone who has your key can spend against your account, so it must be treated like a password: never shared, never posted, never committed to git.

What is a .env file?

A .env file is a plain-text file that holds secrets like API keys, kept out of your code. Programs read from it at runtime. The golden rule: a .env file must never enter git. You keep it out by listing it in a special .gitignore file, which tells git "pretend these files don't exist."

What is Claude Code?

Your coding partner. You type what you want in plain English — "load these three files and tell me what's in them" — and Claude Code does the actual coding, shows you the result, and waits for your next instruction. You stay the decision-maker; it does the typing. It's how a non-engineer builds real software.

Task
  1. Create an API key at the Anthropic Console.

    Why: this is the credential Claude Code uses. Sign in, open API Keys, and create one. Copy it the moment it appears — you won't be able to see it again.

    Browser 
    https://console.anthropic.com/settings/keys
    Stuck?

    No account yet? Create one with your email — creating accounts and entering passwords is something you do yourself, never Claude. Your instructor will confirm billing is set up for the course before you generate a key.

  2. Store the key in a .env file — and make sure git ignores it.

    Why: this is the single most important security habit of the week. The key goes in .env; .env goes in .gitignore; neither the key nor the file ever reaches git.

    .env (create this file — replace with your real key) 
    ANTHROPIC_API_KEY=sk-ant-xxxxxxxxxxxxxxxxxxxx
    .gitignore (add this line) 
    .env
    Stuck?

    How do I know it's really ignored? Run git status. If .env does not appear in the list, git is correctly ignoring it. If it does appear, your .gitignore line is misspelled or in the wrong folder.

  3. Install the Claude Code CLI.

    Why: this puts the claude command on your machine. Follow the official install instructions for your operating system.

    Browser 
    https://docs.claude.com/claude-code
    Terminal 
    claude --version
  4. Start Claude Code and send your first prompt.

    Why: this is the moment it becomes real. Launch claude, then ask it something simple. Read its answer — you're now working with your coding partner.

    Terminal 
    claude
    Claude Code prompt 
    In one short paragraph, explain what you can help me do as my
coding partner this week. Assume I've never written code before.
    Stuck?

    Authentication error? Claude Code can't find your key. Confirm your .env file is in the folder you launched claude from, and that the line reads ANTHROPIC_API_KEY= with no spaces around the equals sign.

Checkpoint

You're done with Cycle 4 when claude --version prints a number, your key lives in a .env that git ignores, and Claude Code has answered your first prompt. Your coding partner is online.

Module 0 — the Meridian kit

≈ 90 min
Concept

Everything you build this week lives in one project: meridian-capstone. It's a ready-made kit — sample data, a bootstrap script, a smoke test, a CLAUDE.md rulebook, and a place for your code. You'll pull a copy to your machine, prove it runs, and take your first look inside.

What is a CLAUDE.md?

A CLAUDE.md is the on-ramp document Claude Code reads every time it opens this project — the rules layer, where you tell Claude Code how to behave in this repo. Think of how a compliance program has a rulebook everyone works from: this file is Claude Code's rulebook. Write a rule here once and it applies to every prompt, without you repeating yourself.

What is cloning a repository?

A repository (or "repo") is a project folder that git tracks. Cloning it means downloading your own full copy, history and all, with one command. From then on it's yours to change locally.

What is a smoke test?

A smoke test is the simplest possible "does it turn on?" check — named for plugging in a device and seeing whether it smokes. It doesn't test everything; it confirms the basics work before you build on top of them. Green smoke test = safe to proceed.

Task
